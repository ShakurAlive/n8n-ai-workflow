# Раскладка нод: что и куда вписывать

Этот файл — справочник по каждой ноде. Если вы импортировали готовый JSON из
папки `n8n/`, сюда стоит заглядывать, когда нода после импорта ругается и надо
понять, что в ней должно быть. Если собираете руками — идите сверху вниз.

Всего четыре воркфлоу:

| Файл | Что делает |
|------|------------|
| `01-draft.json` | принимает фото и видео, генерирует пост, ведёт согласование |
| `02-publish.json` | публикует пост или Reels, потом предлагает сторис |
| `03-schedule.json` | публикует отложенное, чистит зависшие группы |
| `04-errors.json` | ловит любые падения и пишет вам в Telegram |

Разделение не для красоты. Публикация вынесена отдельно, потому что её
запускают из двух мест: сразу после нажатия кнопки и по расписанию. Держать
одну и ту же цепочку в двух копиях — верный способ однажды поправить только
одну из них.

## Чего в этих нодах нет

Двух вещей, которые обычно ожидают увидеть:

**Текстов промптов.** Они лежат в таблице `prompt_templates`, а ноды Gemini
получают готовую строку в поле `{{ $json.prompt }}`. Подробнее — в
`docs/prompts.md`.

**Настроек бренда.** Имя, город, тон, хештеги и токен Instagram лежат в таблице
`accounts`, по строке на каждый аккаунт. В нодах их нет вообще.

Поэтому «поменять стиль постов» и «добавить второй Instagram» — это `update` и
`insert` в базе, а не правка воркфлоу.

# Общие вещи, которые надо понять до начала

## Что такое выражение

Поля в нодах бывают двух режимов: **Fixed** (обычный текст) и **Expression**
(выражение). Переключатель появляется при наведении на поле. В режиме
Expression всё, что внутри `{{ }}`, — это JavaScript, который вычисляется
перед запуском ноды.

`{{ $json.chat_id }}` означает «возьми поле `chat_id` из данных, пришедших в
эту ноду».

`{{ $('Имя ноды').first().json.chat_id }}` — «возьми `chat_id` из результата
ноды с таким именем». Именно поэтому **имена нод менять нельзя**: на них
ссылаются другие ноды.

## Что такое айтем

По проводам между нодами бегут не «данные вообще», а список объектов —
айтемов. Если запрос к базе вернул 5 строк, дальше пойдёт 5 айтемов, и
следующая нода выполнится 5 раз. Это поведение по умолчанию, и оно нам как раз
нужно, чтобы скачать 5 фотографий, не написав ни одного цикла.

Важное следствие: **если нода вернула 0 айтемов, все ноды ниже не выполнятся
вообще**. Мы используем это как механизм остановки вместо ветвлений.

## Query Parameters в нодах Postgres

В поле Query пишем `$1`, `$2` — это заглушки. Реальные значения передаются
отдельно: Options → Add Option → **Query Parameters**, и туда выражение вида

```javascript
{{ [ $json.group_key, $json.user_id ] }}
```

Значения подставятся по порядку. Так подпись с апострофом или кавычкой не
сломает запрос.

# Воркфлоу 1: «Черновик и согласование»

## 1. Telegram Trigger

| Поле | Значение |
|------|----------|
| Credential | ваш бот |
| Updates | `message` |

`callback_query` включать не нужно: кнопками займётся нода Send and Wait,
у неё свой отдельный вебхук.

## 2. Switch — «Что пришло»

Mode: **Rules**. Два выхода, порядок важен — проверки идут сверху вниз.

| Выход | Условие |
|-------|---------|
| `command` | String: `{{ $json.message.text }}` **starts with** `/` |
| `media` | Array: `{{ $json.message.photo }}` **is not empty** <br> **ИЛИ** Object: `{{ $json.message.video }}` **exists** |

У правила `media` два условия, и Combinator надо переключить с `AND` на **`OR`**
— иначе фото и видео должны прийти одновременно, чего не бывает. Обе ветки
ведут в одну и ту же нody: дальше фото и видео обрабатываются общим путём,
разница появляется только перед моделью.

Fallback Output: **None** — всё остальное (обычный текст, стикеры, голосовые)
игнорируем. Проверка на команду стоит первой, потому что команда это тоже
текстовое сообщение, и порядок правил определяет, куда оно попадёт.

## 3. Postgres — «Найти пользователя»

| Поле | Значение |
|------|----------|
| Operation | Execute Query |
| Query | запрос **[1]** из `sql/queries.sql` |
| Options → Query Parameters | `{{ [ $json.message.from.id ] }}` |
| Settings → Always Output Data | **включить** |

`Always Output Data` включаем специально: если человека нет в базе, нода

выполнение просто оборвалось бы молча.

что неизвестно, чьим голосом писать и куда публиковать.

## 6. Edit Fields — «Данные медиа»

Здесь собираем в один плоский объект всё, что понадобится дальше. Режим
Manual Mapping.

Одна нода обслуживает и фото, и видео. Каждое поле — тернарный оператор:
«если пришло видео, берём оттуда, иначе из самого крупного кадра фотографии».
Читается тяжеловато, зато дальше по потоку разницы нет вообще.

Чтобы не писать длинный префикс много раз, в таблице ниже `TG` означает
`$('Telegram Trigger').item.json.message` — в самой ноде надо писать полностью.

| Имя | Тип | Значение |
|-----|-----|----------|
| `group_key` | String | `{{ TG.chat.id }}:{{ TG.media_group_id \|\| 'm' + TG.message_id }}` |
| `user_id` | Number | `{{ $json.user_id }}` |
| `account_id` | Number | `{{ $json.account_id }}` |
| `chat_id` | Number | `{{ TG.chat.id }}` |
| `caption` | String | `{{ TG.caption \|\| '' }}` |
| `media_type` | String | `{{ TG.video ? 'video' : 'photo' }}` |
| `file_id` | String | `{{ TG.video ? TG.video.file_id : TG.photo.sortBy('file_size').last().file_id }}` |
| `file_unique_id` | String | то же с `file_unique_id` |
| `width` | Number | то же с `width` |
| `height` | Number | то же с `height` |
| `file_size` | Number | то же с `file_size` |
| `duration` | Number | `{{ TG.video ? TG.video.duration : null }}` |
| `mime_type` | String | `{{ TG.video ? (TG.video.mime_type \|\| 'video/mp4') : 'image/jpeg' }}` |

Три момента, которые стоят объяснения.

**`sortBy('file_size').last()`.** Telegram присылает одну фотографию в
нескольких размерах — от миниатюры 90×67 до оригинала. Нам нужен самый
крупный. Брать последний элемент массива нельзя: порядок не гарантирован, и на
практике встречается, когда предпоследний кадр больше последнего. Сортировка по
размеру файла надёжна. У видео такой проблемы нет — там один файл.

**`group_key`.** Склеиваем `chat_id` с `media_group_id`. Если файл отправлен
одиночным, `media_group_id` отсутствует, и мы подставляем `m` плюс номер
сообщения — так одиночный файл становится «группой из одного». Чат в ключе
нужен, чтобы два разных пользователя не столкнулись случайными номерами.

**`account_id`.** Приезжает из предыдущей ноды, потому что запрос [1] джойнит
`users` с `accounts` по `active_account_id`. С этого момента и до публикации
воркфлоу знает, в какой аккаунт всё пойдёт, и больше нигде это не выясняет.

| Поле | Значение |
|------|----------|
| Query | запрос **[3]** |

## 9. Wait — «Пауза 10 секунд»

| Поле | Значение |
|------|----------|
| Resume | After Time Interval |
| Wait Amount | `10` |
| Wait Unit | Seconds |

Это и есть ваше требование «фото за 10 секунд считаются одним постом».
Telegram доставляет альбом за доли секунды, но запас лишним не бывает — при
медленном интернете снимки могут растянуться на пару секунд.

## 10. Postgres — «Захватить группу»

| Поле | Значение |
|------|----------|
| Query | запрос **[4]** |
| Query Parameters | `{{ [ $('Данные медиа').item.json.group_key ] }}` |
| Settings → Always Output Data | **выключить** ← критично |

Сердце всей конструкции. Пять выполнений (по одному на файл) одновременно
пытаются перевести группу из `collecting` в `generating`. База обрабатывает
запросы по одному, поэтому условие сработает ровно для первого — он получит
строку и пойдёт дальше. Остальные четыре получат ноль строк и остановятся
прямо здесь, потому что галочка `Always Output Data` выключена.

Никакого кода, никаких проверок «кто лидер». Работу по разруливанию гонок
делает Postgres, для этого он и создан.

Побочная работа этого же запроса — вычислить `media_kind`: `photo`, `video` или
`mixed`. От него зависят и выбор промпта, и способ публикации.

## 11. Postgres — «Медиа и настройки»

| Поле | Значение |
|------|----------|
| Query | запрос **[5]** |
| Query Parameters | `{{ [ $json.id ] }}` |

Вернёт столько айтемов, сколько файлов в группе. К каждому приклеены настройки
аккаунта и — главное — поле `prompt` с **готовым текстом промпта**.

Промпт собирает база: берёт шаблон из `prompt_templates` (свой у аккаунта, если
есть, иначе общий) и подставляет в него значения функцией `render_prompt`. Вид
шаблона выбирается по `media_kind`: для фотографий `draft_photo`, для видео
`draft_video`.

Поэтому ноды Gemini ниже получают просто `{{ $json.prompt }}` и ничего не знают
ни про бренды, ни про режимы. Чтобы изменить стиль текстов, вы делаете `update`
в базе и не открываете n8n.

## 12. Telegram — «Скачать файлы»

| Поле | Значение |
|------|----------|
| Resource | File |
| Operation | Get |
| File ID | `{{ $json.file_id }}` |
| Download | включено |

Нода выполнится по разу на каждый айтем. На выходе — те же айтемы, но с
прикреплённым бинарным файлом в поле `data`.

**Про 20 МБ.** Bot API отдаёт ботам файлы не больше 20 МБ, и обойти это можно
только своим Local Bot API Server. Практически это ролик до минуты. Если файл
больше, нода упадёт с `file is too big` — сообщение уйдёт в воркфлоу 04.

## Развилка: от «Скачать файлы» идут две связи

От этой ноды тянем **два** провода. Причина техническая: нода HTTP Request,
загрузив файл на хостинг, заменяет содержимое айтема ответом сервера, и
бинарник теряется. А он нужен ещё и для Gemini. Две параллельные ветки решают
проблему: каждая получает свою копию айтемов вместе с файлами.

- Ветка А: нода 13 (хостинг картинок)
- Ветка Б: нода 15 (генерация текста)

## 13. HTTP Request — «Залить на Cloudinary»

| Поле | Значение |
|------|----------|
| Method | POST |
| URL | `https://api.cloudinary.com/v1_1/ВАШ_CLOUD_NAME/auto/upload` |
| Send Body | включить |
| Body Content Type | Form-Data |
| Body Parameter 1 | Name `file`, Parameter Type **n8n Binary File**, Input Data Field Name `data` |
| Body Parameter 2 | Name `upload_preset`, Value — имя вашего unsigned-пресета |

Зачем это нужно: Instagram не умеет принимать файл напрямую, ему нужна
публичная HTTPS-ссылка, которую он скачает сам. Ссылки Telegram не годятся —
они привязаны к токену бота и живут недолго.

Почему Cloudinary, а не ImgBB: ImgBB не хранит видео и не умеет обрезать
картинку под сторис. Cloudinary делает и то, и другое, причём обрезка задаётся
прямо в адресе файла — никакой обработки на вашем сервере.

**Про `auto/upload`.** Этот путь заставляет Cloudinary сам определить, картинка
пришла или видео. Если поставить `image/upload`, видео будет отвергнуто.

**Про unsigned-пресет.** Подписанная загрузка требует посчитать SHA-1 от
параметров — это ещё одна нода с кодом. Unsigned-пресет убирает подпись:
загрузка становится обычным POST с двумя полями. Пресет создаётся в Settings →
Upload → Add upload preset → Signing Mode: Unsigned.

Ответ содержит `secure_url` — постоянную HTTPS-ссылку на файл.

## 15. Code — «Склеить медиа»

Одна из двух нод с кодом во всём проекте. Она нужна потому, что Gemini
принимает несколько файлов только внутри одного айтема, а у нас их пять штук в
пяти разных.

Mode: **Run Once for All Items**.

```javascript
const rows = $('Медиа и настройки').all().map((item) => item.json);
const first = rows[0];

const merged = { json: {}, binary: {} };

$input.all().forEach((item, index) => {
  merged.binary[`m${index}`] = item.binary.data;
});

merged.json = {
  group_id: first.group_id,
  chat_id: first.chat_id,
  account_id: first.account_id,
  media_kind: first.media_kind,
  media_count: rows.length,
  has_video: rows.some((row) => row.media_type === 'video'),
  prompt: first.prompt,
  prompt_template_id: first.prompt_template_id,
  brand_name: first.brand_name,
  tg_media: rows.slice(0, 10).map((row) => ({
    type: row.media_type === 'video' ? 'video' : 'photo',
    media: row.file_id,
  })),
};

return [merged];
```

Обратите внимание: промпт нода не собирает, а просто прокидывает дальше — он
пришёл готовым из базы. Раньше тут была вся сборка контекста, теперь нет.

`tg_media` — готовый массив для отправки альбома обратно в Telegram, сразу с
правильным `type` для каждого файла. `.slice(0, 10)` потому, что в медиагруппе
не может быть больше десяти элементов.

Условие: Boolean `{{ $json.has_video }}` **is true**.

- **true** → нода 17 «Описать видео»
- **false** → нода 18 «Описать фото»

Развилка нужна потому, что у ноды Gemini разные ресурсы для картинок и видео.

## 17. Google Gemini — «Описать видео»

| Поле | Значение |
|------|----------|
| Credential | Google Gemini(PaLM) Api |
| Resource | **Video** |
| Operation | Analyze Video |
| Model | `models/gemini-2.5-flash` |
| Text Input | `{{ $json.prompt }}` |
| Input Type | Binary File(s) |
| Input Data Field Name(s) | `{{ Object.keys($binary).join(',') }}` |
| Simplify Output | включено |
| Options → Max Output Tokens | `1200` |
| Settings → Retry On Fail | включить, 3 попытки, 5000 мс |

Лимит выходных токенов поднят специально: модели ветки 2.5 тратят часть
бюджета на внутренние рассуждения, а видео даёт им много материала для
размышлений. С дефолтным лимитом ответ иногда обрывается на середине.

## 18. Google Gemini — «Описать фото»

То же самое, но Resource: **Image**, Operation: Analyze Image, и без поднятого
лимита токенов.

Про креденшелы отдельно: в поле **Host** должен быть только базовый адрес

```text
https://generativelanguage.googleapis.com
```

Без `/v1beta`, без `/models`, без имени модели. Нода дописывает путь сама.
Лишний хвост в Host — самая частая причина ошибки 404 у этой ноды.

Выражение `{{ Object.keys($binary).join(',') }}` подставит `m0,m1,m2` — имена
полей, которые создала нода «Склеить медиа».

## 19. Postgres — «Сохранить текст»

Входит двумя связями: от «Описать видео» и от «Описать фото».

| Поле | Значение |
|------|----------|
| Query | запрос **[8]** |
| Query Parameters | `{{ [ $('Склеить медиа').first().json.group_id, $json.content.parts[0].text, '', $('Склеить медиа').first().json.prompt_template_id ] }}` |

Третий параметр — пустая строка, потому что это первая генерация, а не правка.
Четвёртый запоминает, каким шаблоном сделан текст: потом видно, какая версия
промпта дала какой результат.

## 20. HTTP Request — «Отправить альбом»

Штатная нода Telegram умеет отправлять медиагруппу, но список файлов в ней
задаётся вручную через интерфейс, а у нас их заранее неизвестное количество.
Проще собрать запрос самому.

| Поле | Значение |
|------|----------|
| Method | POST |
| URL | `https://api.telegram.org/bot<ВАШ_ТОКЕН>/sendMediaGroup` |
| Send Body | включить |
| Body Content Type | JSON |
| Specify Body | Using JSON |

JSON:

```json
{
  "chat_id": {{ $json.chat_id }},
  "media": {{ JSON.stringify($('Склеить медиа').first().json.tg_media) }}
}
```

`file_id` можно подставлять везде, где Telegram ждёт ссылку на файл, поэтому
перезаливать ничего не приходится. Массив `tg_media` уже собран в ноде 15 и
содержит правильный `type` для каждого файла, так что видео уйдёт видео, а не
битой картинкой.

Настройка **On Error: Continue** стоит осознанно: если превью не отправилось,
это не повод терять готовый текст.

**Кликабельную ссылку на пост в сторис через API добавить нельзя.** Meta прямо

указан ваш `@юзернейм`. Зритель уходит в профиль, где пост лежит сверху. Это
ровно то, что делают руками.

## 26. Code — «Собрать сторис»

Вторая и последняя нода с кодом в проекте. Собирает адрес трансформации
Cloudinary — картинку 1080×1920 с наложенными надписями.

```javascript
const d = $input.first().json;

const headline = encodeURIComponent(d.story_headline || 'НОВЫЙ ПРОЕКТ');
const subline = encodeURIComponent(d.story_subline || 'подробности в профиле');
const handle = encodeURIComponent(d.ig_username ? '@' + d.ig_username : '');

const layers = [
  'c_fill,w_1080,h_1920,g_auto',
  'e_brightness:-15',
  `l_text:Arial_78_bold:${headline},co_white,g_north,y_280`,
  `l_text:Arial_46:${subline},co_white,g_south,y_360`,
];

if (handle) {
  layers.push(`l_text:Arial_40_bold:${handle},co_white,g_south,y_270`);
}

const overlay = layers.join('/');
let url = d.public_url;

if (d.media_type === 'video') {
  url = url
    .replace('/video/upload/', `/video/upload/so_1/${overlay}/`)
    .replace(/\.(mp4|mov|webm|m4v)$/i, '.jpg');
} else {
  url = url.replace('/upload/', `/upload/${overlay}/`);
}

return [{ json: { ...d, story_image_url: url } }];
```

Что делает каждая часть трансформации:

| Часть | Что делает |
|-------|------------|
| `c_fill,w_1080,h_1920` | обрезает под вертикальный формат сторис |
| `g_auto` | Cloudinary сам ищет, что на кадре главное, и не режет это |
| `e_brightness:-15` | слегка притемняет, чтобы белый текст читался |
| `l_text:Arial_78_bold:...` | накладывает надпись поверх |
| `g_north,y_280` | сверху с отступом; `g_south` — снизу |
| `so_1` | для видео берёт кадр на первой секунде |

Замена расширения на `.jpg` нужна потому, что из видео мы достаём картинку, а
Cloudinary определяет формат результата по расширению в адресе.

`encodeURIComponent` обязателен: текст надписи попадает в путь URL, и пробел или
кириллица без кодирования сломают ссылку.

Почему это код, а не выражение: технически всё уложится в одну строку, но
получится нечитаемое месиво на пол-экрана, которое невозможно править.

Настройка надписей — не в коде, а в базе: поля `story_headline` и
`story_subline` таблицы `accounts`. Код трогают только чтобы поменять шрифт,
размер или положение.

# Воркфлоу 3: «Расписание и уборка»

Два независимых потока в одном файле.

## Поток А: отложенная публикация

1. **Schedule Trigger** — каждые 5 минут.
2. **Postgres «Готовые к публикации»** — запрос **[14]**, без параметров.
3. **Execute Sub-workflow «Опубликовать»** — вызывает воркфлоу 2, передавая
   `group_id` = `{{ $json.group_id }}`.

Чтобы поставить пост в очередь, выполните запрос **[13]** — например, из ветки
согласования, добавив третью кнопку. В минимальной версии отложенную
публикацию можно назначать прямо в базе.

## Поток Б: уборка зависших групп

1. **Schedule Trigger** — раз в час.
2. **Postgres «Почистить зависшее»** — запрос **[19]**.
3. **IF** — если что-то вернулось, **Telegram** с уведомлением админу.

Зачем: если выполнение упало между захватом группы и сохранением текста,
группа навсегда застрянет в статусе `generating`. Повторная отправка тех же
фото ничего не даст — ключ занят. Уборщик переводит такие в `failed`, и о
проблеме становится известно.

# Воркфлоу 4: «Ошибки»

1. **Error Trigger** — срабатывает при падении любого воркфлоу, который на
   него настроен.
2. **Telegram** — сообщение админу:

```text
Ошибка в воркфлоу: {{ $json.workflow.name }}
Нода: {{ $json.execution.lastNodeExecuted }}
Текст: {{ $json.execution.error.message }}
Выполнение: {{ $json.execution.url }}
```

Подключается так: в каждом из воркфлоу 1–3 откройте Settings и в поле
**Error Workflow** выберите «04 Ошибки».

Без этого падения видны только в списке выполнений, куда никто не смотрит,
пока не заметит, что бот молчит.
