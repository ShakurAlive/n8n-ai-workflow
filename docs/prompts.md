# Промпты

**Промпты не лежат в нодах.** Они хранятся в таблице `prompt_templates`, а нода
Google Gemini получает в поле Text Input ровно одно выражение:

```javascript
{{ $json.prompt }}
```

Готовый текст промпта собирает Postgres. В шаблоне стоят дырки вида
`{{brand_name}}`, а SQL-функция `render_prompt` подставляет в них значения из
таблицы `accounts` и данные текущего поста.

Полные тексты шаблонов лежат в `sql/003_accounts_prompts_media.sql` — там они
вставляются в базу при миграции. Этот файл объясняет, **почему** они написаны
именно так и как их менять.

## Как устроена подстановка

```text
prompt_templates.body        accounts + post_groups          нода Gemini
"Ты SMM бренда              brand_name = 'Кухни'            "Ты SMM бренда
 «{{brand_name}}»...    →    caption = 'МДФ эмаль'      →     «Кухни»...
 Комментарий:                                                 Комментарий:
 {{caption}}"                                                 МДФ эмаль"
```

Внутри SQL это выглядит так:

```sql
render_prompt(t.body, jsonb_build_object(
    'caption', coalesce(nullif(g.caption, ''), '(комментария не было)'),
    'brand_name', a.brand_name,
    'tone', a.tone
))
```

Плейсхолдер, которого нет в `jsonb_build_object`, останется в тексте как есть —
это заметно сразу, потому что модель увидит буквальное `{{caption}}`.

### Доступные плейсхолдеры

| Плейсхолдер | Откуда | В каких шаблонах |
|-------------|--------|------------------|
| `{{brand_name}}` | `accounts.brand_name` | все |
| `{{city}}` | `accounts.city` | черновики |
| `{{tone}}` | `accounts.tone` | черновики |
| `{{extra}}` | `accounts.extra_instructions` | черновики |
| `{{hashtags}}` | `accounts.default_hashtags` | черновики |
| `{{caption}}` | подпись к первому файлу | черновики |
| `{{media_count}}` | сколько файлов в группе | `draft_photo` |
| `{{duration}}` | длина видео в секундах | `draft_video` |
| `{{post_text}}` | текущий текст поста | `edit` |
| `{{edits}}` | что попросил поправить владелец | `edit` |

## Виды шаблонов

| `kind` | Когда используется |
|--------|--------------------|
| `draft_photo` | в группе только фотографии |
| `draft_video` | в группе есть видео |
| `edit` | владелец нажал «Внести правки» |

Вид выбирается автоматически по полю `post_groups.media_kind`, которое
вычисляется в момент захвата группы.

## Какой шаблон возьмётся

Запрос ищет шаблон в таком порядке:

1. активный шаблон нужного вида **для этого аккаунта**;
2. если его нет — активный **общий** шаблон (`account_id is null`).

```sql
where t.is_active
  and t.kind = 'draft_photo'
  and (t.account_id = grp.account_id or t.account_id is null)
order by t.account_id nulls last
limit 1
```

`nulls last` и есть весь механизм приоритета: своя строка идёт раньше общей.

Практически это значит, что можно завести аккаунт только про кухни с очень
узким промптом, а все остальные оставить на общем шаблоне. Пример —
`sql/004_example_second_account.sql`.

## Как менять промпт

Быстро, с потерей истории:

```sql
update prompt_templates
set body = 'новый текст'
where account_id is null and kind = 'draft_photo' and is_active;
```

Аккуратно, с сохранением предыдущей версии:

```sql
update prompt_templates set is_active = false
where account_id is null and kind = 'draft_photo' and is_active;

insert into prompt_templates (account_id, kind, body, version, note)
values (null, 'draft_photo', 'новый текст', 2, 'убрал упоминание эргономики');
```

Уникальный индекс разрешает ровно один активный шаблон каждого вида на аккаунт,
поэтому вставить новый, не погасив старый, не получится — база не даст.

Изменения действуют со следующего поста. Перезапускать воркфлоу не нужно.

# Почему шаблоны написаны именно так

## Режим определяется моделью, а не нодой

В `draft_photo` есть явная развилка «РЕКЛАМА или КЕЙС». Можно было поставить
Switch в n8n и держать два разных шаблона, но тогда любое изменение в правилах
бренда пришлось бы вносить в двух местах. Один шаблон с развилкой внутри проще
поддерживать.

## Комментарий владельца важнее картинки

Пункт «факты из комментария важнее того, что видно на фото» стоит первым не
случайно. Модель уверенно и убедительно придумывает материалы и сроки. Явное
указание, чей приоритет выше, убирает большую часть выдумок.

По той же причине в шаблоне есть отдельная фраза про то, что не названные цены
и размеры называть не надо.

## Запрет markdown стоит не из вредности

Telegram с включённым `Parse Mode: Markdown` падает на невалидной разметке, а
Instagram markdown просто не понимает и покажет звёздочки как есть.

## Ограничение в 1200 знаков

Держит текст далеко от лимита Telegram (4096) и внутри разумного для Instagram
(там потолок 2200). Для видео лимит ниже — 1000 знаков, потому что подпись под
Reels в интерфейсе обрезается раньше.

## «Всё, о чём не просили, оставь как было»

Ключевая фраза шаблона `edit`. Без неё модель на каждом круге переписывает пост
заново, и вы бесконечно гоняете её по кругу, теряя удачные формулировки.

## Видео описывается через движение

В `draft_video` отдельно просим обратить внимание на то, что видно только в
динамике: доводчики, подсветку, выдвижные системы, «до и после». Иначе модель
описывает видео как набор статичных кадров, и текст ничем не отличается от
поста по фотографиям — а значит, съёмка видео была напрасной.

# Настройка ноды Gemini

| Параметр | Значение | Почему |
|----------|----------|--------|
| Model | `models/gemini-2.5-flash` | мультимодальная, свободный тир, стабильная версия |
| Text Input | `{{ $json.prompt }}` | промпт приходит готовым из базы |
| Input Type | Binary File(s) | файлы идут телом, не ссылками |
| Input Data Field Name(s) | `{{ Object.keys($binary).join(',') }}` | подставит `m0,m1,m2...` |
| Simplify Output | включено | ответ приходит в удобном виде |

Не берите `models/gemini-flash-latest`: под этим именем Google со временем
подменяет модель, и однажды тон постов поедет сам собой. Для стабильного голоса
бренда нужна зафиксированная версия.

Модели ветки 2.5 тратят часть выходных токенов на внутренние рассуждения. Если
ответы начнут обрываться на середине, поднимите лимит выходных токенов в
Options. У ноды «Описать видео» он уже поднят до 1200.

## Сколько стоит видео

Gemini считает видео примерно по 300 токенов за секунду. Тридцатисекундный
ролик — около 9 тысяч входных токенов, это дороже, чем десять фотографий, но в
бесплатный лимит укладывается спокойно. Ограничение Telegram в 20 МБ всё равно
не даст прислать что-то длиннее минуты.

## Где искать текст ответа

При включённом **Simplify Output** текст лежит здесь:

```javascript
{{ $json.content.parts[0].text }}
```

Если в вашей версии ноды структура другая, запустите ноду один раз, посмотрите
вкладку Output и поправьте выражение. Универсальный вариант на оба случая:

```javascript
{{ $json.content?.parts?.[0]?.text || $json.text }}
```
